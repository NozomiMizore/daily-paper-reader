## 摘要
CASCADE 是一种智能体框架，通过 MCP 暴露的预计算 ARACNe 调控网络，预测基因扰动对下游转录组的影响。先前的工作通过检查预测的基因是否为已知癌症基因（成员关系）来验证此类工具；我们则测试预测的变化方向是否与现实一致，使用焦点基因拷贝数扩增作为敲低逆过程的剂量代理，基于真实的 TCGA 患者肿瘤数据。对于 MYC，CASCADE 预测的敲低靶标在三种癌症类型（BRCA：90.0%，COAD：72.0%，STAD：85.7%；均 p<0.0013）中与真实的扩增与非扩增肿瘤表达高度一致，显著高于置换基线，并通过了 PAM50 亚型对照，且在独立队列（METABRIC，87.2%）中得到重复。与精选的 MSigDB 基因集基线通过 Fisher 精确检验进行比较，CASCADE 的准确性未显示超过已有公开的 MYC 或 E2F 驱动生物学知识，但其基因特异性的方向判定明显优于朴素的统一猜测。扩展到另外 15 个基因后，验证显示是基因特异性的而非普遍性的：增殖机制调控因子大多可重复，而谱系身份转录因子和一个细胞周期蛋白 D 旁系同源物（CCND2）始终失败，我们将这一模式作为一种对冲的事后假说加以讨论。我们另外评估了基于 LLM 的智能体是否能够正确地将自然语言请求映射到 CASCADE 的真实 MCP 工具调用上。在 35 个查询中，一个有记录的本地模型达到 71.4% 的精确匹配（较大模型为 85.7%）；模式和基因别名故障可通过扩大规模或服务器端修正来解决，但两个模型在模糊查询上都自信地默认到错误的扰动类型，这一故障无法通过定向修复解决，因为其触发条件从未出现。

## Abstract
CASCADE is an agentic framework that predicts downstream transcriptional effects of gene perturbation from precomputed   ARACNe regulatory networks, exposed via MCP. Prior work validates such tools by checking whether predicted genes are   known cancer genes (membership); we instead test whether the predicted direction of change matches reality, using   focal-gene copy-number amplification as a dosage-based proxy for the inverse of knockdown against real TCGA patient   tumor data.   For MYC, CASCADE's predicted knockdown targets show strong concordance with real amplified-vs-non-amplified tumor   expression across three cancer types (BRCA: 90.0%, COAD: 72.0%, STAD: 85.7%; all p<0.0013), well above permutation   baselines, surviving a PAM50 subtype control and replicating in an independent cohort (METABRIC, 87.2%). Compared   against curated MSigDB gene-set baselines via Fisher's exact test, CASCADE's accuracy is not shown to exceed existing   public knowledge of MYC- or E2F-driven biology, though its gene-specific direction-calling clearly outperforms a naive   uniform guess.   Extending to fifteen additional genes, validation proves gene-specific rather than universal: proliferation-machinery   regulators mostly replicate, while lineage-identity transcription factors and one cyclin-D paralog (CCND2)   consistently fail, a pattern we discuss as a hedged, post-hoc hypothesis.   We separately benchmark whether an LLM-based agent correctly grounds natural-language requests into CASCADE's real MCP   tool calls. Across 35 queries, a documented local model reaches 71.4% exact match (85.7% for a larger model); schema   and gene-alias failures are resolved by scale or server-side correction, but both models confidently default to the   wrong perturbation type on ambiguous queries, a failure a targeted fix could not resolve because its trigger condition   never occurs.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有基于调控网络的基因扰动预测工具，其验证方式通常只检查"预测的候选基因是否为已知癌症基因"（成员关系验证），而**从未检验预测中最关键的"方向性声明"**——即"该基因在扰动后是上调还是下调"是否与真实疾病中的情况一致。
- **背景**：CASCADE 是继 RegNetAgents 之后的同类智能体框架，均基于 ARACNe 预计算调控网络、LangGraph 工作流与 MCP 协议暴露。RegNetAgents 验证**上游调控因子识别**（成员富集即可）；CASCADE 的任务是预测**下游扰动效应**（需要方向性验证），用成员关系验证显然不够。
- **深层含义**：当此类工具通过 MCP 暴露给 LLM 智能体时，智能体向用户报告的内容继承了工具的验证缺口。因此，作者认为必须**直接面向患者真实数据**验证预测方向的正确性，而非仅凭网络拓扑或基因集归属推断其"合理性"。

## 2. 论文提出的方法论（核心思想、关键技术细节）

### 2.1 核心框架：CASCADE 系统架构

- 输入：焦点基因、TCGA 癌症类型网络、扰动类型（敲低/过表达）。
- 工作流：通过 `CascadeWorkflow.run()` 公开入口执行，先做**基因角色分类**（主调控因子/转录因子/次要调控因子/效应子/孤立基因，基于网络出入度阈值），再据此路由到相应分析模块。
- 本论文所有实验统一使用 `analysis_depth="focused"`、`top_k=50`、默认传播深度 2 跳。

### 2.2 扰动传播算法

- **网络组件**：在 ARACNe 的**有向 regulator→target 边**上执行确定性广度优先（BFS）传播。敲低时焦点基因初始效应为 −1.0；每跳传递时，效应乘以边权与衰减因子 0.5，跨路径累加。
- **边符号机制**：边的模式标注（激活/抑制）决定符号翻转——这是产生方向预测（上/下）的主要机制。
- **嵌入混合（α=0.7）**：将网络信号与 GREmLN 预训练基因嵌入的余弦相似度加权混合。本论文验证嵌入组件不改变方向、只调整幅度，且嵌入唯一添加的目标基因在 27 个组合中均为 0–1 个，排除混杂。

### 2.3 方向一致性验证方法（核心方法论贡献）

- **剂量代理**：以焦点基因的拷贝数扩增（GISTIC=2）作为"敲低逆过程"的近似剂量代理。
- **判断规则**：对每个预测靶基因，比较扩增与非扩增患者样本的 mRNA 表达 z 值均值。预测敲低后下调的基因，若在扩增样本中表达更高则判为一致（反之亦然）。
- **统计显著性**：
  - 单侧二项检验（原假设：一致性率 = 50%）；
  - 独立置换检验：从 200 个背景基因池中随机抽取 50 个基因（排除焦点基因及真实预测集），保持真实上/下比例，进行 1,000 次置换得到经验 p 值；
  - 多组比较采用 Benjamini-Hochberg FDR 校正。

### 2.4 LLM 工具调用接地基准（Agentic 层验证）

- 用 CASCADE 真实 MCP 工具 schema，对 35 个手工标注的自然语言查询（7 个类别 × 5 个查询）测试两个本地 Ollama 模型（llama3.1:8b 与 qwen2.5:72b），按字段逐一比对生成的工具调用参数是否与地面真值匹配。
- 别名错误分两层计分：模型原始输出 vs. 经 CASCADE 服务器端真实 `resolve_alias()` 步骤处理后的结果。

## 6. 论文的主要结论与发现

1. **MYC 预测方向高度准确**：BRCA 90.0%（p<10⁻⁸）、COAD 72.0%（p=0.0013）、STAD 85.7%（p<0.0001），置换 p=0.0000；样本量在 25–100 范围内一致性保持 88–92%，非常稳定。
2. **独立复制成功**：METABRIC 中 87.2%（p<10⁻⁶），排除共享数据伪影；生物学连贯性得到佐证，高置信靶点集中于核糖体生物发生机器（NOP14、RIOK1、WDR43 等）。
3. **泛化呈基因特异性**：9/10 增殖机制基因在至少一种癌种中验证成功（E2F3、CCND1、CCND3、AURKA、CCNE1、MDM2、FOXM1、TOP2A、RPS6KB1），**6 个基因失败**——4 个谱系身份转录因子（SOX9、FOXA1、GATA3、ESR1）、RTK（ERBB2，但 STAD 例外反转为 93.6% 一致）、以及**CCND2**（与验证成功的旁系同源基因 CCND1/CCND3 形成尖锐反例，在所有测试癌种中失败）。
4. **方向判定本身有价值**：将预测统一强制为"下调"使一致性降低 14–29 个百分点；上调预测子集本身也远高于随机水平。
5. **未超越公共知识**：MYC 和 E2F3 方向预测与精选 MSigDB 基线无显著差异。
6. **LLM 工具调用存在三种失败模式**：schematic 符合性失败可通过增大模型规模解决；基因别名失败可经服务器端 `resolve_alias()` 解决；**扰动类型模糊性失败无法修复**——两个模型在模糊查询上都会"自信地猜错"，因为触发条件（字段未设置）从未发生，作者称之为"自信-错误猜测"问题。
7. **提出事后假说**：增殖机制（线性响应剂量） vs. 谱系身份（染色质级非线性响应）假说，但明确声明为对冲性的事后解释，非先验机制，且 CCND2 反例说明该规则不完整。

## 7. 优点：方法与实验设计亮点

- **直接检验方向性声明**：这比成员富集验证严格得多，填补了工具验证与智能体声明之间的逻辑鸿沟。
- **天然实验设计**：用拷贝数扩增作为剂量代理，巧妙规避了缺乏实验扰动数据的问题，且在独立队列上复制成功，因果推断强度较高。
- **多重统计防线**：二项 + 置换 + FDR 三层统计框架，置换基线避免信号污染，设计细致。
- **透明度极高**：全部基因选择来源逐一披露（盲筛/系统/假设驱动/证伪驱动），包括一个专门选来证伪假说的 ESR1；负面与不一致结果均如实报告，未做选择式报告。
- **诚实划定边界**：用 Fisher 检验如实承认"未超越已有公共知识"，不夸大贡献。
- **对 LLM 代理失败模式的细致诊断**：将三种失败模式拆解，并实证发现"针对性修复失效——因为触发条件从不发生"这一反直觉发现，揭示了指令微调模型在枚举字段上的行为特性。

## 8. 不足与局限

- **验证代理的固有近似性**：拷贝数扩增 ≠ 直接敲低实验；基因剂量与活性关系并非线性，个别基因（如 GATA3，其主要致癌驱动是点突变而非扩增）的代理可能根本不成立，这一点作者自认未解决。
- **泛化面板规模受限**：15 个基因、27 个组合远小于系统性验证所需的规模；具有 MYC 级跨组织扩增的基因本身罕见，限制了面板扩展。
- **未能证明超越现有知识**：与 MSigDB 基线无显著差异——CASCADE 的价值在于"无基因特异性注释条件下的合理预测"，而非高于公共知识库的准确性。
- **跨癌种不一致未获解释**：CCND1、MDM2 在 BRCA 验证成功但 STAD 失败；ERBB2 在 BRCA/COAD 反一致而 STAD 强烈一致；CCND2 与其旁系同源基因相反——这些模式只能描述，无法提供机制解释。
- **缺少与邻近方法头对头对比**：未与 CellOracle 等最接近的网络传播方法对比，LINCS L1000 直接实验验证也因覆盖率不足未能实行。
- **LLM 基准规模小**：35 个查询、3 个模糊方向查询、2 个本地模型，无法给出泛化的准确性估计；未测试前沿商业模型；仅评估单步工具调用，未评估多轮行为与错误恢复。
- **事后假说偏差风险**：作者明确承认增殖机制/谱系身份分组是观察到的模式而非预先注册的假设，且 CCND2 是尖锐反例；基因选择序列本身存在事后拟合的可能性。
- **网络局限性**：ARACNe 网络是群体平均的，不捕捉肿瘤亚克隆异质性与个体调控状态；2015 年 TCGA 数据与 2018 年 GDC 数据虽流程不同但可能患者重叠（已用 METABRIC 化解）。
